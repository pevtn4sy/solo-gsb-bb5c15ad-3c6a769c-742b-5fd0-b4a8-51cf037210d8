# 文稿批注迁移工具

供校对人员使用的单机网页工具：在旧版文稿上框选文字写批注，粘贴新版文稿后，系统根据**选中文本 + 前后文**在新稿中自动重新定位批注；无法可靠定位时一律标为「待处理」交给人工，**绝不静默挂到错误段落**。迁移或人工定位后，系统还会对新稿中已定位的批注做**重叠复核**：按半开区间判定重叠并传递合并为冲突组，结果页逐组列出，方便核对多条批注挤在同一段文字的情况。确定位置的批注还可由人工**复核签收**（标记「已核准」或「需调整」并填写备注、记录时间）；结论与当时的新稿全文、批注原文与内容、迁移状态及新区间绑定，重复迁移结果不变则保留，任一绑定值改变即自动清除，避免旧核准误用于新位置。

技术栈：Node.js + Express + 原生前端（无构建步骤），数据以 JSON 文件保存在本机 `data/` 目录。

## 快速开始

### 方式一：Docker（推荐，一条命令）

```bash
docker compose up --build
```

启动后在浏览器打开 **http://localhost:3000** 即可使用；停止用 `Ctrl+C`，后台运行用 `docker compose up --build -d`。

### 方式二：本机 Node.js（≥ 18）

```bash
npm install && npm start
```

### 访问地址与端口

启动后在浏览器打开：**http://localhost:3000**

- 默认端口：`3000`。本机方式可用 `PORT=8080 npm start` 修改；Docker 方式修改 `docker-compose.yml` 中的 `ports` 映射（如 `"8080:3000"`）。
- 数据目录：`./data/documents/*.json`（每份文稿一个文件，Compose 已挂载到容器 `/app/data`，删除容器不丢数据）。

## 使用流程

1. **新建文稿**，在 ① 中粘贴旧版文稿并保存；
2. 在旧稿阅读区**框选文字**，弹出输入框写下批注（可反复添加多条）；
3. 在 ② 中粘贴新版文稿，点击「保存新稿并迁移批注」；
4. 在 ③ 中并排查看：左侧为新稿（高亮定位结果），右侧为每条批注的状态：
   - 🟢 **已定位**：唯一出现，或重复出现但前后文可明确区分；
   - 🟡 **待处理**：原文已删除/改写（附相似片段候选），或多处出现且前后文并列（附全部候选位置）——点击候选即可采用；
   - 🔵 **人工指定**：点击「手动定位」后在左侧新稿中框选文字，即保存为该批注的位置（任何批注都可用此方式修正）。
5. **重叠复核**：凡已确定位置的批注在新稿中发生重叠，结果页顶部会出现「⚠ 批注重叠复核」面板，逐组列出全部批注及其范围（区分**完全相同**与**部分交叠**），点击「跳转到新稿位置」可在左侧定位；新稿中重叠段以橙色虚线标出，点击可弹出该处全部批注逐条查看，不会跳过后续批注。修改任一位置（重新迁移、采用候选、手动定位）后分组即时重算。
6. **人工复核签收**：在每条「已定位 / 人工指定」批注卡片底部填写复核备注（可选），点击「✓ 标记已核准」或「✎ 标记需调整」，系统记录结论、备注与签收时间；卡片与结果页顶部、文稿列表下拉框均显示当前有效的已核准 / 需调整数量。可随时点「修改复核」改判。**待处理、未迁移批注没有确定位置，不能核准。**
7. 所有操作即时保存，无需额外动作；可随时修改新稿后「重新迁移」。

### 复核结论的绑定与自动失效

签收时结论会绑定当时的：**新稿全文**（SHA-256 摘要）、**批注原文**与**批注内容**、**迁移状态**、**新区间** `[start, end)`。

- **重复迁移得到完全相同的结果**（绑定值全部一致）时，结论继续保留；
- **任一绑定值改变**（重新迁移到别处或变为待处理、采用候选 / 手动改位、替换新旧稿、批注原文或内容变化）时，旧结论立即自动清除，卡片与计数同步更新——旧核准不会被误用到新位置；
- 历史文稿 JSON 中缺少复核字段时照常打开，计数按 0 处理。

## 定位规则（核心保证）

| 情况 | 结果 |
|---|---|
| 选中文本在新稿出现 1 次 | 自动定位 |
| 出现多次，比较前后各 80 字符上下文，最高分领先次高分 ≥ 0.3（满分 2） | 自动定位到最高分 |
| 出现多次但上下文得分并列 / 无上下文依据 | **待处理**，列出全部候选位置 |
| 出现 0 次（删除或改写） | **待处理**，附二元组相似度 ≥ 0.45 的相似片段候选 |

匹配对换行、多余空格等空白差异不敏感（归一化后比对，位置映射回原文）。

## 重叠复核规则

每次迁移或人工定位后，系统对已确定位置的批注即时重算重叠分组：

| 规则 | 说明 |
|---|---|
| 参与范围 | 仅「已定位 / 人工指定」的批注；**待处理、未迁移批注不入组** |
| 重叠判定 | 按半开区间 `[start, end)`：`a.start < b.end` 且 `b.start < a.end`；**端点相接（`a.end === b.start`）不算重叠** |
| 分组方式 | 重叠关系传递合并：A 叠 B、B 叠 C，则 A/B/C 同属一个冲突组 |
| 组类型 | 组内范围完全一致 → **完全相同**；否则 → **部分交叠** |
| 结果展示 | 结果页顶部逐组列出全部批注及范围，可跳转到新稿位置；重叠段高亮中每条批注都可点击选中 |

分组为派生数据：随每个文稿接口的响应（`overlapGroups` 字段）即时计算返回，不写入磁盘，因此修改任一位置后分组立即更新。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/documents` | 文稿列表 |
| POST | `/api/documents` | 新建文稿 `{title}` |
| GET / DELETE | `/api/documents/:id` | 详情 / 删除 |
| PUT | `/api/documents/:id/old` | 保存旧稿 `{oldText}`（自动重算批注上下文） |
| POST | `/api/documents/:id/annotations` | 添加批注 `{start, end, comment}` |
| DELETE | `/api/documents/:id/annotations/:aid` | 删除批注 |
| PUT | `/api/documents/:id/new` | 保存新稿 `{newText}` |
| POST | `/api/documents/:id/migrate` | 执行迁移 |
| PUT | `/api/documents/:id/annotations/:aid/position` | 人工指定位置 `{start, end}` |
| PUT | `/api/documents/:id/annotations/:aid/review` | 复核签收 `{decision: 'approved' \| 'changes', note?}`（待处理/未迁移批注返回 400） |

> 所有返回文稿的接口都会在响应中附带 `overlapGroups`（重叠冲突组，按当前位置即时计算）、`approvedCount` / `changesCount`（当前有效的复核数量）。复核结论存于批注的 `review` 字段，内含 `decision`、`note`、`at`（签收时间）与 `binding`（绑定快照）。

## 项目结构

```
server.js            Express 服务与 API
lib/match.js         批注重定位核心算法
lib/overlap.js       新稿批注重叠分组（半开区间 + 传递合并）
lib/review.js        人工复核签收（绑定快照、有效性校验、失效清除与计数）
public/              原生前端（index.html / app.js / style.css）
test/match.test.js   定位算法单元测试
test/overlap.test.js 重叠分组单元测试
test/review.test.js  复核绑定与自动失效单元测试
data/                文稿与批注数据（运行时生成）
Dockerfile / docker-compose.yml
```

## Docker Compose 一键启动

`docker-compose.yml` 已构建镜像、映射端口并挂载数据卷，无需其他依赖：

```bash
docker compose up --build      # 前台启动，日志直接输出
docker compose up --build -d   # 后台启动
docker compose down            # 停止
```

- 访问端口：**http://localhost:3000**（修改 `docker-compose.yml` 的 `ports` 可换端口）；
- 数据持久化：当前目录 `./data` 挂载到容器 `/app/data`。
